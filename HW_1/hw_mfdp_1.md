1.  Бизнес-анализ (Business Understanding)
Организационная структура проекта
Со стороны заказчика в проекте участвуют врачи-рентгенологи, ответственный представитель от организации заказчика, юрист, а также специалисты, отвечающие за медицинские информационные системы (МИС) и программное обеспечение рентгенологического оборудования.
Со стороны команды разработки участвуют ML-специалисты, data scientists, backend- и frontend-разработчики, DevOps и менеджер проекта.
Основные пользователи сервиса — врачи-рентгенологи.
Создаётся рабочий чат в согласованном мессенджере. В него включаются представители заказчика и команда разработчиков.
Цель проекта — разработать инструмент поддержки врача-рентгенолога для автоматической детекции подозрительных структур легочной ткани на КТ органов грудной клетки.
Проект направлен на:
1.	Оптимизацию труда врачей-рентгенологов: снижение рутинной нагрузки без расширения штата.
2.	Снижение риска диагностических ошибок: особенно при высокой нагрузке и длительной монотонной работе.
3.	Повышение качества медицинской услуги: модель используется как инструмент предварительной ‘подсветки’ подозрительных структур легочной ткани. 
NB! Окончательное решение остаётся за врачом.
4.	Увеличение пропускной способности диагностического отделения: за счёт ускорения первичного анализа исследований и приоритизации случаев, требующих внимания врача.
Несмотря на наличие коммерческих решений для выявления лёгочной патологии на КТ, заказчику может потребоваться собственное или адаптируемое решение, интегрируемое в локальный рабочий процесс, учитывающее особенности данных конкретной медицинской организации и позволяющее контролировать качество модели на собственных исследованиях.
Возможные ограничения:
1.	высокая стоимость лицензии и внедрения;
2.	сложность интеграции с локальной медицинской информационной системой, оборудованием и ограниченная адаптация к локальным клиническим протоколам;
3.	отсутствие прозрачности работы модели;
4.	необходимость соблюдения локальных требований к хранению и обработке медицинских данных (новые законы);
5.	возможное снижение качества при переносе модели на данные конкретной клиники из-за отличий в протоколах КТ, оборудовании и популяции пациентов.


1.1 Текущая ситуация (Assessing current solution)
Для реализации проекта потребуется доступ к КТ-изображениям органов грудной клетки, данным разметки и экспертной поддержке врачей-рентгенологов.
Железо.
Для первичного прототипа можно использовать доступные вычислительные ресурсы: локальный компьютер, Google Colab/Kaggle или облачный GPU-сервер. Для полноценного обучения модели на больших объёмах КТ-данных может потребоваться GPU с достаточным объёмом видеопамяти. Если у заказчика нет такого оборудования, потребуется аренда облачных вычислительных мощностей или закупка GPU-сервера.(находящиеся на территории РФ)
Хранение данных.
Данные КТ обычно хранятся в медицинской информационной системе в формате DICOM. Для проекта необходимо получить доступ к обезличенным КТ-исследованиям с заключением (и желательно разметкой) врача-рентгенолога..
Внешние данные.
На этапе прототипа можно использовать открытые датасеты КТ органов грудной клетки. На этапе внедрения желательно дополнительно проверить модель на данных конкретной клиники, потому что протоколы КТ, оборудование и структура пациентов могут отличаться.
Эксперты.
Заказчик должен выделить врачей-рентгенологов для консультаций: уточнения клинически значимых признаков, проверки качества разметки, оценки ошибок модели и финальной клинической апробации модели.
Риски и снижение рисков
Риск 1. Не уложиться в сроки.
Сначала сделать модель для детекции подозрительных структур на ограниченной выборке, затем постепенно добавлять улучшения: расширение данных, визуализацию, интеграцию с интерфейсом.
Риск 2. Недостаточное количество данных.
Использовать открытые датасеты для первичного обучения (их не мало представлено в открытом доступе) и дополнительно запросить локальные обезличенные данные у заказчика.
Риск 3. Низкое качество данных или разметки.
Провести разведочный анализ данных, удалить технически непригодные исследования, проверить часть разметки врачом-рентгенологом, согласовать критерии «подозрительной структуры».
Риск 4. Дисбаланс классов.
План снижения: использовать балансировку классов и метрики, устойчивые к дисбалансу.
Риск 5. Модель хорошо работает на открытом датасете, но хуже на данных клиники.
Провести внешнюю валидацию на локальных данных заказчика и при необходимости дообучить модель.
Риск 6. Результаты модели окажутся недостаточно полезны врачу.
Заранее согласовать формат результата: не просто вероятность, а подсветка подозрительной зоны, уровень уверенности модели и возможность врачу быстро принять или отклонить подсказку.
Риск 7. Юридические ограничения.
Использовать только обезличенные данные, согласовать доступ с юристом и не позиционировать модель как самостоятельный диагностический инструмент.

1.2 Решаемые задачи с точки зрения аналитики (Data Mining goals)
С точки зрения машинного обучения проект относится к задачам computer vision.
В самом начале, вполне будет достаточно бинарной классификации (есть патология/нет патологии)
На следующем этапе модель может не только выдавать вероятность наличия подозрительных структур, но и показывать область изображения, на которой она определяется.
Критерий успешности модели
•	Recall (TPR) — минимизирует риск пропуска патологии. Для медицинской задачи это ключевой показатель: лучше получить лишнее подозрение и направить снимок врачу, чем пропустить патологическое изменение.
Критерий успеха:
•	минимально приемлемо: Recall ≥ 0.85 
•	хороший результат: Recall ≥ 0.90 
•	целевой результат: Recall ≥ 0.95

•	Fβ-score - F2-score — это вариант Fβ-score, где Recall важнее Precision. То есть модель получает более высокую оценку, если она хорошо находит патологию, даже если иногда ошибочно помечает нормальные снимки как подозрительные.
Критерий успеха:
	минимально приемлемо: F2 ≥ 0.80 
	хороший результат: F2 ≥ 0.85 
	целевой результат: F2 ≥ 0.90

•	FPR / False Positive Rate — контрольная метрика
Показывает долю здоровых случаев, которые модель ошибочно отметила как подозрительные. Позволяет контролировать нагрузку на врача, чтобы модель не гиперболизировала и не срабатывала на все сигналы
Критерий успеха:
	желательно удерживать FPR ≤ 0.20–0.25, если при этом сохраняется высокий Recall.

•	Fβ-score - F1-score — дополнительная метрика, помогает оценить, не достигается ли высокий Recall ценой слишком большого числа ложных срабатываний.Можно принять следующие показатели метрики за успех
Критерий успеха:
	минимально приемлемо: F1 ≥ 0.75 
	хороший результат: F1 ≥ 0.80–0.85




1.3 План проекта (Project Plan)
1. Определение задачи (Business Understanding)

* Цель: разработка ML-модели для помощи врачам-рентгенологам
* Бизнес-ценность: снижение нагрузки и повышение качества диагностики
* Формулировка задачи: бинарная классификация КТ (патология / норма) на первом этапе далее с улучшением модели возможна многоклассовая классификация (выявленная патология опухоль, саркоидоз, туберкулез, пневмония, гемобластоз и т.д. )


2. Работа с данными (Data Collection & Understanding)

* Выбор датасета 
* Первичный анализ данных (EDA)
* Оценка качества и разметки данных


3. Подготовка данных (Data Preparation)

* Очистка данных (удаление шумов, ошибок)
* Нормализация/аугментация изображений
* Разделение на train / validation / test


4. Разработка модели (Modeling)

* Выбор архитектуры (базовая CNN или предобученная модель компьютерного зрения)
* Обучение модели
* Подбор гиперпараметров


5. Оценка качества (Evaluation)

* Метрики
* Анализ ошибок модели
* Сравнение с базовыми подходами


6. Внедрение и тестирование (Deployment)

* Тестирование на врачах-рентгенологах
* Интеграция в МИС
* Подготовка презентации продукта
* План масштабирования
