# LungPrometheus

**LungPrometheus** — end-to-end ML-сервис для детекции патологических узлов на КТ грудной клетки. Дипломный проект программы «Инженер машинного обучения» (ИТМО).

Идея простая: врач загружает КТ-исследование, модель за секунды находит подозрительные узлы и подсвечивает их на срезах, а сервис формирует текстовое заключение. Ниже — путь от сырых DICOM-файлов до работающего веб-сервиса.

## Результаты модели

Классификатор «узел / не узел» на 3D-патчах КТ превысил целевые показатели проекта по всем метрикам:

| Метрика | Результат | Цель |
| --- | --- | --- |
| F2-score | 0.948 | ≥ 0.90 |
| F1-score | 0.919 | ≥ 0.85 |
| FPR | 0.19 | ≤ 0.20–0.25 |

Проведён сравнительный бенчмаркинг с коммерческими решениями (Veye Lung Nodules, AI-Rad Companion, InferRead Lung CT.AI, Целс.КТ).

## Что внутри

**Пайплайн данных.** Нормализация DICOM, извлечение 3D-патчей 32×32×32, стратифицированное разделение train/val/test (70/15/15), аугментация.

**Модель.** 3D CNN, обученная на PyTorch.

**Веб-сервис.** Загрузка и просмотр КТ (DICOM, .mhd/.raw), запуск анализа через очередь фоновых воркеров, подсветка находок, ручное добавление находок врачом, генерация текстового заключения через FastAPI и локальную LLM (Ollama).

**Инфраструктура.** REST API, SQLite, Docker/Docker Compose, тесты.

## Возможности

### Просмотр КТ

Загрузка отдельных DICOM-файлов, загрузка серии DICOM, поддержка исследований в формате `.mhd + .raw`, загрузка всей папки исследования, просмотр срезов, масштабирование изображения.

### Анализ

Запуск анализа исследования, выполнение анализа в фоне через очередь задач, масштабирование числа воркеров модели, отображение найденных объектов, возможность добавить находку вручную.

### Пользователи

Регистрация, авторизация, тестовый баланс пользователя, списание стоимости анализа — 80 ₽, заполнение данных пациента перед загрузкой исследования.

### Генерация заключения

После завершения анализа сервис обращается к отдельному FastAPI-приложению, которое взаимодействует с Ollama и формирует текстовое заключение.

Если Ollama недоступна, используется резервный шаблон заключения, поэтому демонстрационная версия продолжает работать без ошибок.

## Основные сущности

Проект использует три основные доменные модели.

**Study.** Хранит информацию об исследовании пациента: данные пациента, описание исследования, текущий статус анализа.

**Finding.** Представляет найденный патологический объект. Может быть автоматически создан моделью или добавлен врачом вручную.

**AnalysisJob.** Описывает задачу анализа, которую обрабатывает один из фоновых воркеров.

## Хранение данных

Используется SQLite. При первом запуске автоматически создаются таблицы `users`, `studies`, `findings`, `analysis_jobs`.

База данных по умолчанию находится по адресу:

```text
data/app.sqlite3
```

## REST API

### Авторизация

| Метод | URL | Назначение |
| --- | --- | --- |
| `POST` | `/api/auth/register` | Регистрация пользователя |
| `POST` | `/api/auth/login` | Вход пользователя |
| `GET` | `/api/auth/me` | Получение текущего пользователя |

### Баланс

| Метод | URL | Назначение |
| --- | --- | --- |
| `POST` | `/api/balance/top-up` | Тестовое пополнение баланса |

### Исследования

| Метод | URL | Назначение |
| --- | --- | --- |
| `GET` | `/api/studies` | Получить список исследований |
| `POST` | `/api/studies` | Создать исследование |
| `GET` | `/api/studies/{id}` | Получить исследование |
| `DELETE` | `/api/studies/{id}` | Удалить исследование |

### Находки

| Метод | URL | Назначение |
| --- | --- | --- |
| `POST` | `/api/studies/{id}/findings` | Добавить находку вручную |

### Анализ

| Метод | URL | Назначение |
| --- | --- | --- |
| `POST` | `/api/studies/{id}/analyze` | Запустить анализ исследования |
| `GET` | `/api/jobs/{id}` | Проверить статус задачи |
| `POST` | `/api/viewer/analyze` | Найти объект для подсветки в загруженных срезах |

### Заключение

| Метод | URL | Назначение |
| --- | --- | --- |
| `POST` | `/api/reports/generate` | Создать заключение через FastAPI/Ollama |

## Пример работы через API

Вход под тестовым пользователем:

```bash
curl -X POST http://127.0.0.1:8765/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin"}'
```

Пополнение тестового баланса:

```bash
curl -X POST http://127.0.0.1:8765/api/balance/top-up \
  -H "Content-Type: application/json" \
  -H "X-Auth-Token: TOKEN" \
  -d '{"amount":80}'
```

Создание исследования:

```bash
curl -X POST http://127.0.0.1:8765/api/studies \
  -H "Content-Type: application/json" \
  -H "X-Auth-Token: TOKEN" \
  -d '{"patient_name":"Иван Петров","patient_id":"P-001","description":"КТ грудной клетки"}'
```

## Быстрый старт

Запуск основного сервиса:

```bash
python3 backend/server.py
```

Запуск сервиса генерации заключений:

```bash
uvicorn backend.report_service:app --host 127.0.0.1 --port 8766
```

При использовании локальной Ollama:

```bash
ollama serve
ollama pull llama3.1
```

По умолчанию используются:

```text
OLLAMA_URL=http://127.0.0.1:11434/api/generate
OLLAMA_MODEL=llama3.1
```

После запуска интерфейс доступен по адресу:

```text
http://127.0.0.1:8765
```

Порт, путь к базе данных и количество воркеров можно изменить при запуске:

```bash
python3 backend/server.py --port 9000 --db data/demo.sqlite3 --workers 4
```

## Docker

Сборка и запуск:

```bash
docker compose up --build
```

Сервис будет доступен по адресу:

```text
http://127.0.0.1:8765
```

Количество воркеров модели задается в `docker-compose.yml`:

```yaml
environment:
  MODEL_WORKERS: 2
```

Чтобы увеличить число воркеров, измените значение переменной, например на `4`, и перезапустите контейнер.
